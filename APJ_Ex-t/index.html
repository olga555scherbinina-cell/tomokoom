Методы REST API и их назначение

Вот основные семь методов REST API (их также называют HTTP-глаголами), каждый из которых выполняет определённую операцию с ресурсом:

МетодНазначениеИдемпотентностьБезопасность
GET📌 Получение данных (запрос информации о ресурсе)ДаДа
POST➕ Создание нового ресурса (отправка данных на сервер)НетНет
PUT🔄 Полное обновление ресурса (замена всех данных)ДаНет
PATCH✏️ Частичное обновление ресурса (изменение отдельных полей)НетНет
DELETE❌ Удаление ресурсаДаНет
HEADℹ️ Получение метаданных (как GET, но без тела ответа)ДаДа
OPTIONS🔍 Определение поддерживаемых методов (например, CORS-запросы)ДаДа

Пояснения:

GET — используется для чтения данных (например, получение списка пользователей).

GET /api/users

POST — применяется для создания нового ресурса (например, добавление пользователя).

POST /api/users
Body: { "name": "John", "age": 30 }

PUT — полностью заменяет ресурс новыми данными (если ресурса нет — может создавать его).

PUT /api/users/1
Body: { "name": "John Doe", "age": 31 }

PATCH — частично обновляет ресурс (изменяет только указанные поля).

PATCH /api/users/1
Body: { "age": 32 }

DELETE — удаляет ресурс.

DELETE /api/users/1

HEAD — аналогичен GET, но возвращает только заголовки (без тела). Используется для проверки доступности ресурса.

OPTIONS — показывает, какие методы поддерживаются для конкретного эндпоинта. Важен для CORS.

Дополнительные термины:

  • Идемпотентность — означает, что повторный вызов метода с теми же данными не изменит результат (например, два DELETE подряд дадут одинаковый эффект).
  • Безопасность — метод не изменяет состояние сервера (например, GET только читает данные).
  • Эндпоинт (Endpoint) — это URL-адрес API, к которому можно обратиться для выполнения конкретной операции. Эндпоинт = Точка входа для взаимодействия с API.
  • CORS (Cross-Origin Resource Sharing) — это механизм, который разрешает или запрещает браузеру запрашивать ресурсы с другого домена.

Отличия методов REST API

PUT vs PATCH

МетодДействиеТело запросаИдемпотентностьПример использования
PUTПолная замена ресурсаДолжно содержать все поляДаОбновление всего профиля пользователя
PATCHЧастичное обновлениеТолько изменяемые поляНетСмена пароля или аватара

➡️ PUT перезаписывает весь ресурс, PATCH меняет только указанные поля.

GET vs HEAD

МетодОтветИспользованиеПример
GETЗаголовки + телоПолучение данныхЗагрузка страницы товара
HEADТолько заголовкиПроверка ресурсаПроверка доступности файла

➡️ GET возвращает данные, HEAD — только метаинформацию.

Простая аналогия:

  1. PUT — как перезапись всей книги vs PATCH — исправление одной страницы.
  2. GET — как прочитать письмо полностью vs HEAD — только посмотреть на конверт.

Эти методы помогают серверу понять, какое действие нужно выполнить, чтобы не обрабатывать лишнее!

Статус-коды ответов сервера

Статусы HTTP отвечают за описание результата обработки запроса клиентом. Они сгруппированы по диапазонам чисел, где первая цифра обозначает класс статуса:

1xx — Информационные коды

  • 100 Continue («продолжайте») — Сервер принял начальную часть запроса и ожидает продолжение.
  • 101 Switching Protocols («переключение протоколов») — Сервер переключил протокол связи согласно запросу клиента.
  • 102 Processing («идёт обработка») — Сервер получил запрос и начал обработку, операция ещё выполняется.
  • 103 Early Hints («предварительный ответ») — Предоставляет предварительные подсказки для улучшения производительности.

2xx — Успешные запросы

  • 200 OK («хорошо») — Запрос выполнен успешно.
  • 201 Created («создано») — Ресурс успешно создан.
  • 202 Accepted («принято») — Запрос принят, но обработка ещё не завершена.
  • 203 Non-Authoritative Information («информация не авторитетна») — Ответ предоставлен кэширующим прокси-сервером.
  • 204 No Content («нет содержимого») — Запрос выполнился успешно, но возвращаемых данных нет.
  • 205 Reset Content («сбросить содержимое») — Клиенту рекомендуется сбросить представление документа.
  • 206 Partial Content («частичное содержимое») — Вернулась лишь часть запрашиваемых данных.
  • 207 Multi-Status («многостатусный») — Используется для веб-коллекций, где один запрос затрагивает сразу несколько ресурсов.
  • 208 Already Reported («уже сообщалось») — Сообщение было отправлено ранее и повторяется снова.
  • 226 IM Used («использовано IM») — Применено расширение протокола для обработки расширенных метаданных.

3xx — Перенаправления

  • 300 Multiple Choices («множество выборов») — Существует несколько возможных адресатов для ресурса.
  • 301 Moved Permanently («перемещено навсегда») — Адрес ресурса изменился окончательно.
  • 302 Found («найдено») — Временное перенаправление на новый ресурс.
  • 303 See Other («смотреть другое») — Редирект на другой адрес для последующего просмотра.
  • 304 Not Modified («не изменялось») — Кэшированные данные всё ещё актуальны.
  • 305 Use Proxy («использовать прокси») — Необходимо воспользоваться указанным прокси-сервером.
  • 306 — зарезервировано (код использовался только в ранних спецификациях).
  • 307 Temporary Redirect («временное перенаправление») — Перенаправление временно, последующий запрос должен быть отправлен на старый адрес.
  • 308 Permanent Redirect («постоянное перенаправление») — Постоянное изменение адреса ресурса, последующие запросы также будут направляться на новый адрес.

4xx — Ошибки клиента

  • 400 Bad Request («неправильный, некорректный запрос») — Некорректный синтаксис запроса.
  • 401 Unauthorized («не авторизован») — Требуется авторизация для доступа к ресурсу.
  • 402 Payment Required («необходима оплата») — Зарезервировано для использования в будущем.
  • 403 Forbidden («запрещено (не уполномочен)») — Доступ запрещён даже при наличии авторизации.
  • 404 Not Found («не найдено») — Запрашиваемый ресурс не найден.
  • 405 Method Not Allowed («метод не поддерживается») — Метод запроса не поддерживается данным ресурсом.
  • 406 Not Acceptable («неприемлемо») — Формат представления данных не поддерживается.
  • 407 Proxy Authentication Required («необходима аутентификация прокси») — Авторизация необходима через прокси-сервер.
  • 408 Request Timeout («истекло время ожидания») — Клиент долго не отвечал на запрос.
  • 409 Conflict («конфликт») — Запрос конфликтует с состоянием текущего ресурса.
  • 410 Gone («удалён») — Ресурс больше не доступен и не имеет точного нового местоположения.
  • 411 Length Required («необходима длина») — Необходимо указать длину передаваемого тела.
  • 412 Precondition Failed («условие ложно») — Предусловия, указанные в запросе, не выполнены.
  • 413 Payload Too Large («полезная нагрузка слишком велика») — Размер запроса превышает допустимый лимит.
  • 414 URI Too Long («URI слишком длинный») — Длина адреса ресурса слишком велика.
  • 415 Unsupported Media Type («неподдерживаемый тип данных») — Неподдерживаемый тип медиаконтента.
  • 416 Range Not Satisfiable («диапазон не достижим») — Диапазон запрашиваемых байтов недопустим.
  • 417 Expectation Failed («ожидание не оправдалось») — Невозможно удовлетворить ожидание клиента.
  • 418 I'm a teapot («я — чайник») — Юмористический код, используемый для демонстрации понимания стандартов.
  • 419 Authentication Timeout (not in RFC 2616) («обычно ошибка проверки CSRF») — Время ожидания аутентификации истекло.
  • 421 Misdirected Request («заблудившийся запрос») — Сервер некорректно выбран для указанного запроса.
  • 422 Unprocessable Entity («необрабатываемый экземпляр») — Полученные данные имеют правильный формат, но содержат семантические ошибки.
  • 423 Locked («заблокировано») — Объект заблокирован и не подлежит обработке.
  • 424 Failed Dependency («невыполненная зависимость») — Операция зависит от успешного выполнения предыдущей команды.
  • 425 Too Early («слишком рано») — Недостаточное ожидание отклика сервера.
  • 426 Upgrade Required («необходимо обновление») — Обновите версию протокола.
  • 428 Precondition Required («необходимо предусловие») — Для выполнения необходимы предусловия.
  • 429 Too Many Requests («слишком много запросов») — Превышен лимит частоты запросов.
  • 431 Request Header Fields Too Large («поля заголовка запроса слишком большие») — Размеры полей заголовков превышают установленные сервером лимиты.
  • 449 Retry With («повторить с») — Повторите запрос с указанием необходимых изменений.
  • 451 Unavailable For Legal Reasons («недоступно по юридическим причинам») — Контент удалён вследствие законодательных ограничений.
  • 499 Client Closed Request (клиент закрыл соединение) — Пользователь разорвал соединение до окончания передачи данных.

5xx — Ошибки сервера

  • 500 Internal Server Error («внутренняя ошибка сервера») — Неопознанная внутренняя ошибка сервера.
  • 501 Not Implemented («не реализовано») — Методы или функциональность пока не поддерживаются сервером.
  • 502 Bad Gateway («плохой, ошибочный шлюз») — Плохой шлюз или неверный ответ от промежуточного сервера.
  • 503 Service Unavailable («сервис недоступен») — Сервис временно перегружен или отключён для обслуживания.
  • 504 Gateway Timeout («шлюз не отвечает») — Промежуточный сервер не дождался ответа от исходного сервера.
  • 505 HTTP Version Not Supported («версия HTTP не поддерживается») — Используемая версия протокола HTTP не поддерживается.
  • 506 Variant Also Negotiates («вариант тоже проводит согласование») — Конфликты в процессе согласования параметров запроса.
  • 507 Insufficient Storage («переполнение хранилища») — Недостаточно памяти для хранения запрошенного ресурса.
  • 508 Loop Detected («обнаружено бесконечное перенаправление») — Детектирована бесконечная рекурсивная цепочка перенаправлений.
  • 509 Bandwidth Limit Exceeded («исчерпана пропускная ширина канала») — Исчерпаны ресурсы полосы пропускания.
  • 510 Not Extended («не расширено») — Необходимые расширения отсутствуют.
  • 511 Network Authentication Required («требуется сетевая аутентификация») — Нужно пройти дополнительную проверку сети.
  • 520 Unknown Error («неизвестная ошибка») — Неопределённая ошибка сервера.
  • 521 Web Server Is Down («веб-сервер не работает») — Основная система веб-сервера не доступна.
  • 522 Connection Timed Out («соединение не отвечает») — Соединение закрыто из-за длительного отсутствия отклика.
  • 523 Origin Is Unreachable («источник недоступен») — Основной источник недоступен.
  • 524 A Timeout Occurred («время ожидания истекло») — Время ожидания истекло.
  • 525 SSL Handshake Failed («квитирование SSL не удалось») — Проблемы с рукопожатием SSL/TLS.
  • 526 Invalid SSL Certificate («недействительный сертификат SSL») — Неверный или просроченный SSL-сертификат.

JSON

Как расшифровывается JSON?

JSON расшифровывается как JavaScript Object Notation (нотация объектов JavaScript). Это текстовый формат обмена данными, основанный на синтаксисе JavaScript, но являющийся независимым от языка.

Преимущества JSON над XML и YAML

Преимущества JSON перед XML:

  • Меньший объем данных: JSON не требует закрывающих тегов, что делает его более компактным.
  • Более простой синтаксис: JSON проще читать и писать.
  • Быстрее парсится: JSON парсится быстрее благодаря более простой структуре.
  • Лучшая интеграция с JavaScript: JSON является подмножеством JavaScript.
  • Нет необходимости в схеме: В отличие от XML, JSON часто используется без схемы.

Преимущества JSON перед YAML:

  • Более строгий синтаксис: JSON имеет четкие правила форматирования.
  • Безопаснее: YAML может выполнять произвольный код при парсинге.
  • Более широкое применение в веб-API: JSON является стандартом для веб-API.
  • Быстрее парсится: JSON парсеры обычно быстрее YAML парсеров.

Что такое JSON Schema?

JSON Schema — это спецификация для аннотирования и валидации JSON-документов. Она позволяет:

  • Описывать структуру JSON-данных.
  • Определять обязательные поля и их типы.
  • Задавать ограничения на значения (минимальные/максимальные значения, регулярные выражения).
  • Обеспечивать валидацию JSON-документов перед их обработкой.

Что такое сериализация и десериализация в контексте JSON?

Сериализация (в контексте JSON) — это процесс преобразования объекта в языке программирования в строку JSON. Например, преобразование объекта Python в JSON-строку.

import json

data = {
    'name': 'Иван',
    'age': 30,
    'city': 'Москва'
}

json_data = json.dumps(data)
print(json_data) # {"name": "Иван", "age": 30, "city": "Москва"}

Десериализация — обратный процесс преобразования JSON-строки в объект языка программирования. Например, преобразование JSON-строки в объект Python.

import json

json_string = '{"name": "Иван", "age": 30, "city": "Москва"}'
parsed_data = json.loads(json_string)
print(parsed_data['name']) # Иван

ООП в Java, Enum, Generics

Объектно-ориентированное программирование (ООП)

ООП — парадигма программирования, основанная на представлении программы в виде совокупности взаимодействующих объектов, каждый из которых является экземпляром определённого класса.

  • Инкапсуляция — механизм, скрывающий внутренние детали реализации объекта и предоставляющий доступ к данным только через public-методы. Модификатор private делает члены класса доступными только внутри самого класса, защищая данные от прямого внешнего изменения.
  • Наследование — механизм создания нового класса на основе существующего. Производный класс наследует поля и методы базового. Ключевое слово: extends. Пример: class Dog extends Animal {}
  • Полиморфизм — способность объектов разных классов обрабатываться через общий тип (родительский класс или интерфейс). Позволяет писать гибкий код, работающий с разными типами объектов единообразно.
  • Абстракция — выделение существенных характеристик объекта, отличающих его от других, определяя его концептуальную границу. Абстрактные классы и интерфейсы задают «контракт» без реализации.

Интерфейсы

Интерфейс — контракт, определяющий набор методов, которые должен реализовать класс. Ключевое слово: implements. Один класс может реализовывать множество интерфейсов. Пример: public class MyClass implements Data, Serializable {}

Enum (перечисления)

Enum — специальный тип, представляющий фиксированный набор констант. Каждая константа — экземпляр enum-класса. Метод ordinal() возвращает порядковый номер (с 0), valueOf("NAME") — константу по строке (регистр важен).

public enum Day { MONDAY, TUESDAY, WEDNESDAY, THURSDAY, FRIDAY, SATURDAY, SUNDAY }
Day day = Day.WEDNESDAY;
System.out.println(day.ordinal());    // 2
Day d = Day.valueOf("WEDNESDAY");     // регистр важен! "wednesday" — ошибка

Generics (Обобщения)

Generics — механизм, позволяющий создавать классы, интерфейсы и методы, работающие с разными типами данных, сохраняя типобезопасность. Параметр типа обозначается в угловых скобках <T>.

class Box<T> { private T value; }                      // generic-класс
interface Container<T> { T get(); }                     // generic-интерфейс
public <T> void print(T item) {}                        // generic-метод
class Child<T> extends Parent<T> {}                     // наследование generic
class Impl<T> implements Container<T> {}                // реализация generic-интерфейса

Память в Java (Stack, Heap, Garbage Collector)

Stack

  • LIFO (Last In, First Out) — последний пришёл, первый ушёл.
  • Статическая память: примитивы, ссылки на объекты.
  • Выделяется и освобождается автоматически при входе/выходе из метода.

Heap (Куча)

  • Динамическая память: Java-объекты, JRE классы.
  • Young Generation (Eden + Survivor spaces) — новые объекты.
  • Old Generation — долгоживущие объекты.

Garbage Collector (сборщик мусора)

  • Автоматически удаляет объекты, на которые больше нет ссылок.
  • Работает в Heap, освобождая неиспользуемую память.
  • Типы: Serial GC, Parallel GC, G1 GC, ZGC.
